# Optimize-Media

CLI tool to compress images and videos optimally on Windows, with SMB/network path support, GPU acceleration (NVIDIA NVENC), and detailed before/after reporting.

## Language rule

**Everything in code, comments, console output, and documentation must be in English.** Vietnamese (or any other language) is only allowed in projects that explicitly implement multi-language i18n. This project has no i18n — always use English.

## Usage

```powershell
# One-time setup (installs all required tools)
.\setup.ps1

# Compress a folder or file (local path or UNC/SMB)
.\Optimize-Media.ps1 -Path "\\NAS\share\path\to\media"

# Presets
.\Optimize-Media.ps1 <path> -Preset fast      # fastest
.\Optimize-Media.ps1 <path> -Preset balanced  # default
.\Optimize-Media.ps1 <path> -Preset max       # maximum compression (AV1 on RTX 40xx)
.\Optimize-Media.ps1 <path> -Preset archive   # H.264 for legacy devices

# Options
.\Optimize-Media.ps1 <path> -Backup           # keep originals in .\backup\
.\Optimize-Media.ps1 <path> -WhatIf           # scan and estimate only
.\Optimize-Media.ps1 <path> -Force            # recompress already-processed files
.\Optimize-Media.ps1 <path> -Codec h264       # force video codec
```

Or drag-and-drop a folder onto `Optimize-Media.cmd`.

## Files

- `setup.ps1` — one-time tool installer (ffmpeg, oxipng, pngquant, jpegoptim); auto-runs the benchmark
- `Optimize-Media.ps1` — main CLI; parallel runspace pools (images on CPU, videos on GPU), in-place progress UI
- `Benchmark-Machine.ps1` — measures CPU/RAM/NVENC sessions, writes `performance` defaults to `config.json` (preserves user tuning unless `-Force`)
- `Optimize-Media.cmd` — drag-and-drop wrapper
- `tools\` — portable binaries (auto-downloaded by setup, gitignored)
- `logs\` — CSV reports + processing history (gitignored, may contain private paths)
- `backup\` — original files when using `-Backup` (gitignored)
- `config.json` — machine-specific tool paths + GPU info + performance tuning (gitignored, regenerated by setup)

## Architecture notes

- Parallelism: two runspace pools (image workers / video workers), counts from `config.json > performance`, overridable per-run via `-ImageWorkers` / `-VideoWorkers`
- Workers return result objects; the main thread harvests completed runspaces every 250 ms and renders a fixed status block via `[Console]::SetCursorPosition` (falls back to periodic lines when output is redirected)
- All console output, comments, and docs must stay in English (see Language rule)
- StrictMode is on: wrap pipeline results that may be a single object in `@()` before using `.Count`
